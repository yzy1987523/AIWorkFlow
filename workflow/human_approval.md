# 人工审批接口

> 定义当工作流需要人类介入时的交互机制

## 概述

在某些场景下，AI工作流无法自动做出决策，需要人类进行审批或确认。

## 需要人工审批的场景

| 场景ID | 场景名称 | 触发条件 | 响应时限 |
|-------|---------|---------|---------|
| APP_001 | 契约变更审批 | 影响力评分 >= 15 | 30分钟 |
| APP_002 | 需求变更审批 | 产品提出需求变更 | 60分钟 |
| APP_003 | 异常升级 | 任务持续失败 | 15分钟 |

## 通知机制

### 通知渠道
- 企业微信/钉钉
- 邮件
- Webhook回调

### 审批通知示例

```json
{
  "type": "approval_request",
  "scene": "CONTRACT_CHANGE",
  "title": "需要审批：契约变更请求",
  "content": {
    "request_id": "CHG-2026-001",
    "impact_score": 18.5,
    "affected_tasks": ["task-002", "task-003"]
  },
  "actions": [
    {"id": "approve", "label": "批准"},
    {"id": "reject", "label": "驳回"}
  ]
}
```

## 审批接口

### REST API

```yaml
# 获取待审批列表
GET /api/v1/approvals

# 审批操作
POST /api/v1/approvals/{approval_id}/action
```

### 审批流程

```
任务执行中...
      │
      ↓
触发需要审批的场景
      │
      ↓
主Agent创建审批请求
      │
      ↓
发送通知给审批人
      │
      ↓
等待审批（超时自动升级）
      │
      ↓
┌─────────────────────────────┐
│      审批人处理             │
│  ┌─────────┐ ┌─────────┐    │
│  │ 批准    │ │ 驳回    │    │
│  └────┬────┘ └────┬────┘    │
│       │           │         │
│       ↓           ↓         │
│  更新契约    要求替代方案    │
│       │           │         │
│       └─────┬─────┘         │
│             ↓               │
│       继续执行              │
└─────────────────────────────┘
```

---

*本接口定义了完整的审批流程，确保人类能够有效介入AI工作流的决策过程。*
