# 需求变更管理流程

> 定义当产品需求发生变化时的工作流处理机制

## 概述

需求变更是开发过程中的常见情况。本文档定义如何识别、评估和处理需求变更。

## 变更流程

```
产品提出变更
      │
      ↓
┌──────────────────┐
│ 变更申请验证      │ ← 主Agent
└────────┬─────────┘
         │
    ┌────┴────┐
    ↓         ↓
  通过      驳回
    │         │
    ↓         ↓
影响评估    通知产品
      │
      ↓
┌──────────────────┐
│ 影响范围分析      │ ← 架构Agent
└────────┬─────────┘
         │
         ↓
   ┌─────┴─────┐
   ↓           ↓
影响小      影响大
   ↓           ↓
自动处理    人工审批
```

## 变更申请格式

```yaml
change_request:
  id: "REQ-CHANGE-2026-001"
  type: "FEATURE_ENHANCEMENT"
  
  applicant:
    role: "product"
    agent_id: "product_agent_001"
  
  change:
    target_task: "task-002"
    description: |
      变更描述
    expected_behavior: |
      期望行为
    reason: |
      变更理由
    priority: "HIGH"
```

## 影响评估

### 评估维度
- 任务影响
- 代码影响
- 进度影响
- 风险影响

### 决策规则

| 影响评分 | 处理方式 |
|---------|---------|
| < 5 | 自动批准 |
| 5-15 | 架构师审核 |
| >= 15 | 人工审批 |

---

*需求变更管理确保了变更的可控性和可追溯性。*
